# 试卷数据格式

每套试卷是 `public/papers/` 下的一个 JSON 文件，文件名就是试卷 id（如 `kaoyan1-2025.json`）。
写好或改完试卷后运行：

```bash
npm run check:papers
```

这个命令会检查格式，并重新生成试卷目录 `public/papers/index.json`。有问题的试卷不会进入目录，命令会列出具体哪里不对。四六级另有一条目录规则（只收 6 月、12 月的正式场次，不收样卷和只有作文翻译的空卷），见 `scripts/check-papers.mjs` 的 `unlisted()` 和 `docs/缺失真题清单.md`。

完整例子见 `public/papers/kaoyan1-2019.json`（完形、阅读、新题型、翻译、写作）和 `public/papers/cet4-sample-2016.json`（含听力）。

> 内容来源要合法：自己整理、录入的试卷才能放进来。不要使用从其他网站抓取或下载的题库、PDF、音频和解析。

## 整体结构

```jsonc
{
  "id": "kaoyan1-2025",          // 必须和文件名一致
  "exam": "kaoyan1",             // kaoyan1 / kaoyan2 / cet4 / cet6
  "year": 2025,
  "month": 12,                   // 可选，四六级用来区分 6 月和 12 月
  "set": 1,                      // 可选，四六级的第几套
  "title": "2025 年考研英语（一）",
  "sample": false,               // 可选，true 时在目录里显示"示例"
  "note": "……",                  // 可选，显示在试卷顶部的提示
  "durationMinutes": 180,        // 可选
  "pdf": {                       // 必填，原卷 PDF 和单词坐标
    "src": "/papers/pdf/kaoyan1-2025.pdf",
    "words": "/papers/pdf/kaoyan1-2025.words.json"
  },
  "audio": { … },                // 可选，听力音频，见下文
  "sections": [ … ]
}
```

## 原卷 PDF

所有试卷都按原卷 PDF 显示，题目就在卷面上做：点题号（完形也可以点文章里的空位）选答案，点单词查词，用笔、高亮、下划线和便签做笔记。JSON 里的题目、选项、答案和解析是给答题卡、判分和解析用的。

试卷 JSON 由导入脚本从 PDF 生成，不用手写：

- `npm run import:kaoyan -- 2019`：`data/raw/kaoyan/` 里的考研英语（一）真题和答案 PDF（去掉页脚水印）
- `npm run import:sample`：考试院大纲里的四级官方样卷
- `npm run import:cet`：`真题/` 里的四六级历年真题，见下面"导入四六级真题"

和原卷相关的字段：

| 字段 | 位置 | 说明 |
| --- | --- | --- |
| `pdf` | 试卷 | 必填。`src` 是原卷 PDF，`words` 是每页可点击单词的坐标和句子，都放在 `public/papers/pdf/` |
| `page`、`box` | 题目 | 必填。题号在第几页（从 1 开始）、页内位置 `[x0, y0, x1, y1]`（PDF 点，原点在左上角） |
| `blank` | 题目 | 完形填空文章里的空位 `{ page, box }`，在空位上也能作答，选好的词直接显示在空位里 |
| `anchor` | 部分 | 部分标题的位置 `{ page, box }`：顶栏切换部分时滚到这里；专项训练从这里截到下一部分的标题之前 |
| `anchor` | 题组 | 听力题组那行的位置，播放按钮放在这里 |
| `from` | 部分 | 卷面没印、从同场另一套接过来的部分（那一套的 id），见下面"四六级第 3 套的听力"；专项训练和题型统计不重复算 |
| `shared` | 试卷 | 接过哪些部分：`[{ section, from, basis }]`，`basis` 是接这一套的依据（原卷说明原文或选择理由） |
| `heading` | 试卷 | 卷面大标题，如"2019 年全国硕士研究生入学统一考试英语（一）试题" |
| `label` | 试卷 | 真题、官方样卷，显示在目录和考场顶栏 |
| `subtitle` | 部分 | 如 `Part A` |
| `kind: "order"` | 部分 | 段落排序（新题型）；段落写成 `"A. ……"` |
| `sequence` | 题组 | 段落排序的顺序，如 `["41", "42", "F", "43", "44", "C", "45"]`：数字是空位，字母是已给出位置的段落 |
| `[[46\|句子]]` | 翻译文章段落 | 划线句，前面显示 (46) |

文章文字（`passage`）也保留在 JSON 里，方便以后做专项训练和搜索。

## 部分（section）

```jsonc
{
  "id": "s1",                    // 本卷内唯一
  "part": "Section I",           // 显示在标题上方，如 Part II / Section I
  "title": "Use of English",
  "kind": "cloze",               // listening / cloze / reading / translation / writing
  "directions": "Read the following text…",  // 可选
  "groups": [ … ]
}
```

`kind` 决定排版方式：

| kind | 用途 | 说明 |
| --- | --- | --- |
| `cloze` | 完形填空 | 文章里用 `{{题号}}` 标出空位 |
| `reading` | 阅读理解 | 文章在上，题目在下 |
| `listening` | 听力 | 通常没有文章；用 `audioSegment` 关联音频分段 |
| `translation` / `writing` | 翻译、写作 | 题目不写 `options`，就是主观题，在右侧"作答"面板里写 |

## 题组（group）

一篇文章和它下面的题目是一个题组。

```jsonc
{
  "id": "s2g1",
  "title": "Text 1",             // 可选
  "audioSegment": "news1",       // 可选，听力题组对应的音频分段 id
  "passage": {                   // 可选
    "title": "……",               // 可选
    "paragraphs": ["第一段……", "第二段……"]
  },
  "questions": [ … ]
}
```

## 题目（question）

选择题：

```jsonc
{
  "id": "q21",                   // 全卷唯一，作答记录按这个保存，发布后不要改
  "number": 21,                  // 题号；完形填空的题号要和文章里的 {{21}} 对应
  "stem": "According to Paragraph 2, …",   // 可选，完形题一般没有
  "options": [
    { "key": "A", "text": "……" },
    { "key": "B", "text": "……" }
  ],
  "answer": "B",
  "explanation": "解析，支持中文"   // 可选，交卷后显示
}
```

主观题（翻译、写作）：

```jsonc
{
  "id": "w1",
  "number": 0,
  "label": "作文",               // 可选，代替题号显示
  "stem": "题目要求，可用 \n 换行",
  "reference": "参考答案，可用 \n 换行"
}
```

## 解析层（explain/）

导入时带的原始解析（`explanation`、`reference`）往往有 PDF 残留：标签丢字、页脚、英文单词粘连、全文翻译混在最后一题里。
`npm run polish:explain` 把它们整理成统一格式，写到单独的解析层 `public/papers/explain/<试卷 id>.json`，应用加载试卷时叠上去：

```jsonc
{
  "id": "cet4-2024-06-1",
  "questions": {
    "q27": {
      "text": "【语法判断】空格前是名词短语……\n【语义判断】……故 required 符合语境。",
      "by": "official"             // official：整理自官方解析；ai：官方没有或残缺，由 AI 补写（界面标"AI 解析"）
    },
    "q46": { "text": "……", "by": "official", "flag": "truncated" },   // 整理后仍有问题，等 AI 重写
    "w1": { "reference": "参考范文……", "by": "official" }
  },
  "groups": {
    "rc1": { "translation": "这篇文章的全文翻译" }
  }
}
```

- 解析每段一个小标题：`【定位】【详解】【排除】`（阅读、听力）、`【语法判断】【语义判断】`（选词填空、完形）
- 解析层和试卷文件分开：重新导入试卷不会冲掉解析；`polish:explain` 可以反复跑，`by: "ai"` 的条目一直保留（AI 写的都核对过答案；想换回官方解析就删掉那一条再跑）；结构化字段 `fields` 不论官方还是 AI 条目也一直保留
- 解析 PDF 里答案取错、对照原卷核实过的题，更正写在 `scripts/cet_answer_fixes.json`（每条写依据），导入时生效
- 导入时会核对解析和原卷是否同一份：阅读解析里引用的英文要大部分能在原卷里找到，否则这套跳过（资料包里文件名的"（2）（3）"不一定是套号）
- `flag` 的含义：`truncated` 开头丢了、`garbled` 题干引文和正文搅在一起、`unclear` 看不出答案依据、`short` 太短

### 结构化字段 fields

每个条目除了旧的自由文本 `text`（保留做回退），还可以带结构化的 `fields`，界面按它排成"定位、思路、逐项、生词"几块；没有 `fields` 的条目界面退回 `text`。由 `scripts/structure_explanations.py` 校验后写入（内容是人/AI 按原卷逐题读过写的，不是脚本生成）：

```jsonc
"q12": {
  "text": "……", "by": "official",
  "fields": {
    "answer": "C",                              // 必须等于答案键
    "locate": {
      "where": "第二段第三句",                    // ≤ 24 字
      "quote": "Praise can become an expectation",   // 原文里连续的一句，≤ 25 词，英文原样
      "page": 3, "words": [412, 418],           // 脚本补的：quote 在 words.json 该页 w[] 里的起止序号（含）；匹配不上就没有
      "line": { "segment": "conv1", "index": 7 } // 听力：逐字稿行号，由 align_transcripts.py 按 quote 补；听力题没有 page/words
    },
    "reasoning": "题干问…… → 原文说…… → 所以选 C",   // ≤ 120 字；选词填空、完形没有这项，改写 grammar + meaning
    "grammar": "空格前是 be，应填过去分词或形容词",    // 选词填空、完形（≤ 80 字）
    "meaning": "句意是……，rewarded 符合",           // 选词填空、完形（≤ 120 字）
    "options": { "A": "原文未提及", "B": "偷换概念：……", "D": "与原文相反" },   // 只写错误项，每项 ≤ 30 字
    "mapping": [{ "stem": "view … as a chance", "text": "place more value on" }],   // 段落匹配：题干词 ↔ 原文表达
    "vocab": [{ "w": "expectation", "zh": "期望" }],   // 3–5 个，词必须出现在原文里
    "translation": "定位句的中文"
  },
  "fieldsBy": "ai",                              // 写 fields 的人：ai
  "fieldsVersion": 1,
  "fieldsFlag": "quote"                          // 可选：通过 --lenient 放行的问题（quote：卷面上没匹配到）
}
```

- **选择题**：`answer`、`locate`、`vocab`、`translation` 都要；阅读、听力要 `reasoning` 和三个错误项的 `options`；选词填空、完形要 `grammar` + `meaning`；段落匹配（Section B）要 `reasoning` + `mapping`，`options` 可省；段落排序（考研新题型）和选词填空的选项有 7–15 个，`options` 只写最有迷惑性的几个（键必须在"该题选项 − 答案"里）
- **翻译、写作**（没有 `answer`）：`points`（2–4 条要点：写作是行文结构，翻译是句式和处理办法）、`phrases`（3–6 条 `{ en, zh }` 亮点表达）
- **卷面上标出**：`locate.page` 和 `locate.words` 给界面做临时高亮。`quote` 在 words.json 里按词匹配（每个词比前 7 个字母，允许约 15% 不一致，同一行内词序被打乱也认），句子跨页或被页脚打断时只标出其中一段；匹配不到就只留 `where`/`quote`
- **听力**：`quote` 是逐字稿里的一句（脚本核对它在这一段逐字稿里出现）；逐字稿行号 `line` 不由本脚本写（行会重新切句），用 `align_transcripts.py --relink-explain` 按 `quote` 补
- **重跑不丢**：`npm run polish:explain` 对任何条目（官方、AI）都原样保留 `fields`、`fieldsBy`、`fieldsVersion`、`fieldsFlag`
- 原来没有解析文本的题，写入 `fields` 时同时用它拼一段旧格式的 `text`（`by: "ai"`）做回退

写入流程见 `scripts/structure_explanations.py` 文件头：`prep` 生成每题输入（原文、选项字母、答案键、现有解析）→ 写批次文件 → `merge` 校验并合并（答案对键、`quote` 能在卷面/逐字稿匹配、`options` 键合法、`vocab` 在原文里、各项长度）→ `status` 看覆盖率。`npm run structure:explain -- status`。`scripts/answer_audit.py` 也会核对 `fields.answer` 和答案键。

## 听力音频（audio）

```jsonc
"audio": {
  "src": "/audio/cet4-2025-06-1.mp3",   // 放在 public/audio/ 下
  "duration": 1620.5,                   // 总时长（秒）
  "segments": [
    {
      "id": "news1",
      "label": "News Report One",
      "start": 0.5,                     // 本段起止时间（秒）
      "end": 95.2,
      "lines": [                        // 听力原文，一句一行带时间，播放时同步高亮（见下面"听力逐字稿"）
        { "start": 0.8, "end": 2.98, "text": "Part II Listening Comprehension.", "kind": "directions" },
        { "start": 38.14, "end": 49.67, "text": "Six people had to move away …" },
        { "start": 111.5, "end": 115.7, "text": "Questions 1 and 2 are based on …", "kind": "cue" },
        { "start": 116.65, "end": 121.99, "text": "Question 1. Why did …?", "kind": "question" }
      ]
    }
  ]
}
```

逐句时间可以用音频编辑软件（如 Audacity）的标签功能标出来再填进来。示例卷的音频是用 `npm run build:audio` 根据 `scripts/audio/` 里的台词合成的，那个脚本会自动算好时间，只适合做演示。

## 听力逐字稿

四六级真题的录音导入时先按静音切成碎片（只有 `start`/`end`），`npm run align:transcripts` 把解析 PDF 里的"听力原文"对到碎片上，再**按句重切**：`lines[]` 最后是一句一行。

| 字段 | 说明 |
| --- | --- |
| `start` / `end` | 这一句的起止时间（秒）。一句跨几个碎片的，取第一个碎片的 `start`、最后一个的 `end`；一个碎片里有句子分界的，按字符数比例切开 |
| `text` | 这一句的英文原文 |
| `speaker` | `"M"` / `"W"`，只有对话的原文句有（原文里 `M:` `W:` 开头的）；说话人换了一定断句 |
| `kind` | 不是原文的句子才有：`"directions"` 指导语，`"cue"` 读题句，`"question"` 读题；原文句没有这个字段 |

**一句**：按 `. ? !` 后面接大写切（`Mr.` `U.S.` `p.m.` `No. 36` 不切），说话人换了切；读题 `Question N.` 和它的题干合成一行（`Question 1. Why did …?`）。识别丢了句号的，只在录音停顿处、下一个词是常见句首词（The、It、So、But……）时补切；读题句粘在上一句后面的切开。没有文字的碎片（作答静音、杂音、没对上原文的指导语）去掉。

**`kind` 只认固定说法**（`classify()`，认不出的一律当原文，不猜）：

- `directions`：`Part II Listening Comprehension.`、`Section A.`、`Directions: In this section, you will hear …`、`At the end of each … you will hear … questions.`、`Both the … and the questions will be spoken only once.`、`The recordings will be played only once.`、`After you hear a question, you must choose the best answer …`、`Then mark the corresponding letter on Answer Sheet 1 …`，以及录音里念的段标题 `News Report One.`（样卷有）
- `cue`：`Questions 1 and 2 are based on …` / `Questions 5 to 7 are based on …`
- `question`：以 `Question N` 开头的那一行（界面靠它认题号刻度，正则 `^Question (\d+)\b`）

一个题组（一个 `audio.segments[]`）里的顺序固定：

1. 本节的指导语（`kind: "directions"`；只有录音里念了的才有，通常是每节第一个题组前面的 `Section A. Directions: …`；解析里没有这一段，用卷面上的固定文字补，带和不带各对一遍、取更贴合时长的）
2. 原文（没有 `kind`）
3. `Questions 1 and 2 are based on the news report you have just heard.`（`cue`）
4. `Question 1. 题干`（`question`，题干来自解析的"答案详解"；没找到题干的只有 `Question 1.`）
5. （作答静音，不在任何一句里）
6. `Question 2. 题干`……

每组第 2 题起的 `Question N` 是导入时按作答静音标的碎片，对齐时是锚点；第 1 题的读题按对齐结果切出。界面播放时默认跳过 `directions`；段开头没对上文字的指导语（被去掉的碎片）也一起跳过。

### 对齐方法

脚本 `scripts/align_transcripts.py`（导入时 `import_cet.py` 会自动调用，重导不丢）：

1. **取原文**：解析 PDF 有文字层的直接用；扫描件用高清重新识别（300dpi，识别宽度放宽、空格概率调低，只识别听力原文那几页，结果缓存在 `data/cache/cet-script-ocr/`，可以删，删了重跑会重新识别，一套约 8 页、每页半分钟到一两分钟）。按标题 `News Report One` / `Conversation One` / `Passage One` / `Recording One` 把原文分到题组（没有标题的版式，改按 `Questions 1 and 2 are based on…` 那一行定位）。取标题后面连续的英文行，碰到汉字行（答案详解、听前预测）或第一题的题号就停；去掉页脚、`[1]` `(1-1)` 这类定位标记、粘在一起的词（按词频拆开）。
2. **分句**：按 `. ? !` 后面接大写切（`Mr.` `U.S.` `p.m.` `No. 36` 不切）；`M:` `W:` 起头的是说话人。
3. **题干**：解析里每道题的英文题干（`1. What …` 后面的英文，截到汉字译文之前）。题干没带题号、直接跟在原文后面的版式，取原文末尾恰好 N 句疑问句（N 是这个题组的题数）。
4. **对到时间**：每个分段独立做一次动态规划，每一行分到连续的几个词：代价 = 这一行时长和字数（约 15 字符/秒，对完按实际校准）的偏差 + 把一行切在句子中间的惩罚（句末最便宜，逗号次之）+ 一行跨两个说话人的惩罚；允许一行没有词（代价较高），用来放过指导语里原文没有的句子。`Question N` 行是锚点：这一行必须从 `Question N.` 这个词开始，把动态规划切成小段。
5. **按句重切**：对完以后按上面的规则切成一句一行、标 `kind`（`sentence_lines()`：每个词的时间按它在碎片里的字符位置比例算）。段的 `id`、`start`、`end` 不动。
6. **原始碎片**：按静音切的碎片存在 `data/cache/cet-audio-lines/<id>.json`（段的 id 和起止要和试卷一致才用）。单独重跑本脚本时从这里重新对齐，所以可以反复跑；缓存删了，只能按现有的句子重标 `kind`（要重新对齐就重新导入）。没有解析 PDF 的样卷不对齐，只按文字切句、标 `kind`。

### 命令

```bash
npm run align:transcripts                              # public/papers/ 里所有有录音的卷子（每套打印 碎片数 → 句数 和各 kind 的句数）
npm run align:transcripts -- cet4-2024-06-1            # 只对这一套
npm run align:transcripts -- --report                  # 只打印报告（每段碎片数、有字的碎片、句数、词/秒、原文质量），不写文件
npm run align:transcripts -- --show cet4-2024-06-1     # 打印对齐后的每一句（带时长、词/秒、kind），人工看
npm run align:transcripts -- --ocr-only                # 只做高清识别（多进程），先跑这个再对齐会快很多
npm run align:transcripts -- --relink-explain          # 解析层里听力题的 fields.locate.quote → fields.locate.line（最像的那一句）
```

报告里"词/秒"是这一段有字的碎片的平均语速，不在 2–3.5 之间的标"语速异常"（多半是录音里有很长的、原文里没有的静默或杂音行，该段的时间对得上，但个别行的文字可能偏一两句）；"原文质量"是识别出的单词里词表里有的比例，低于 0.93 标"文字质量低"。

### 已知的局限

- 文字来自扫描件识别，个别词有错字（`Faye tt evil le` 这样把人名拆碎的、`7o,000` 这样的数字，已经尽量处理，剩下的会有）。
- 句子的起止在碎片内部时是按字符数比例估的，可能差零点几秒。
- 原文识别丢了句号、下一句又不是常见句首词开头的（`… diagnoses Researchers have …`），两句会并成一行。
- 有的录音里有很长的、不是原文的杂音或静默碎片（几秒到十几秒），这些碎片没有文字，按句重切时去掉了，播放时照常会播到。
- `--relink-explain` 只在原文句里找（不看指导语和读题），按 quote 的相邻词对重合度取最像的一句（每个词只比前 7 个字母），重合太少的不填；它只改 `line` 这一个字段，最近 2 分钟内改过的解析层文件跳过。
- 指导语是按固定文字补的，不是从录音听写的；录音里实际念的可能略有出入。

## 答案核对

`npm run audit:answers`（`scripts/answer_audit.py`，给人用，不会改任何文件）：每套卷子把三方的答案对一遍——答案键、官方解析正文里说的答案（`polish_explanations.py` 里的 `ANSWER_SAID` 正则）、解析层里 AI 解析结尾的答案；不一致的题列成表（也写在 `data/cache/answer-audit.md`）。选词填空解析多半只写词、不写字母，另外按原卷词库（`A–O` 各是哪个词）核对：解析结尾提到的词不是键对应的词，就标出来。目的是让人花十来分钟抽查：确认键确实错了，把更正写进 `scripts/cet_answer_fixes.json`（写上依据，导入时生效）。`npm run audit:answers -- cet4-2024-06-1` 只看一套，`--all` 连没问题的套也列出来。

## 新增一套试卷

1. 先检查 PDF：`npm run inspect:pdf -- 文件.pdf`。"可以导入"才能直接用；"文字层乱码"可以改用 Word 版；"扫描件"要先 OCR。
2. 四六级真题库在项目根目录的 `真题/` 下：`真题/四级/2024年12月/2024年12月四级第1套-真题.pdf`，同一套还有 `-解析.pdf`（答案、解析、听力原文）、`-听力.mp3`、`-真题.docx`。`真题/清单.md` 列出每场每套有什么、缺什么、能不能直接导入。新买的资料包放进 `真题/`，运行 `npm run organize:cet` 整理进来（只收 2015 年以后的真题），再运行 `npm run organize:cet -- --clean` 把资料包移到回收站（要在自己的终端里运行，沙箱里回收站不可写）。
3. 考研真题和答案 PDF 放进 `data/raw/kaoyan/`（这个目录不进版本库），给 `scripts/import_kaoyan.py` 加上这一年的修正表；四六级真题用 `npm run import:cet`，见下一节。
4. 运行导入脚本，再运行 `npm run check:papers`：会检查每道题有没有在原卷上定位、答案在不在选项里。
5. 打开 `npm run dev`，在卷面上把整卷做一遍，确认题号标记的位置和答案。

## 导入四六级真题

```bash
npm run import:cet -- cet4-2025-12-1          # 导入一套（四级、2025 年 12 月、第 1 套）
npm run import:cet -- --all                   # 全部能导的都导，最后列出每套的状态
npm run import:cet -- --list                  # 只看每套有哪些文件
npm run import:cet -- --all --no-ocr          # 不识别扫描页，需要识别的套先跳过
npm run import:cet -- --all --no-ocr --dry-run # 只检查每套能不能导、为什么跳过，不写任何文件（也不删旧文件），状态存在 data/cache/cet-import-dryrun.json
npm run check:papers
```

脚本在 `scripts/import_cet.py`，配合 `scripts/cet_answers.py`（从解析 PDF 取答案、解析、参考作文和译文）和 `scripts/cet_ocr.py`（扫描页文字识别）。每套输出：

- `public/papers/<id>.json`：写作、听力、阅读、翻译；题号、选词填空的空位、听力题组（"Questions 1 and 2 are based on…" 那一行）、各部分标题都定位在原卷上。阅读拆成三个部分：`reading-a`（选词填空，kind `banked`）、`reading-b`（段落信息匹配，kind `matching`）、`reading-c`（仔细阅读，kind `reading`，两篇文章两个题组），各有自己的 `anchor`（Part III 里的 "Section A/B/C" 标题行）
- `public/papers/pdf/<id>.pdf` 和 `.words.json`：原卷。卖家的二维码和店铺水印会去掉；扫描页按原件分辨率重做，最多 300dpi（平板 2 倍屏放大到 140% 还清楚；原件 600、1200dpi 的按面积缩小），黑白扫描存成灰度并洗白背景、压黑文字，JPEG 质量 72，一份 9 页的卷子约 4–5 MB；矢量文字的小文件、又没有要去的东西，就是 `真题/` 里文件的硬链接
- `public/audio/<id>.mp3`：听力录音（硬链接）。录音里每道题后有约 15 秒作答静音，共 25 段，按这个把录音分到各题组（`audio.segments`），每段再按停顿切成"句"（`lines`，先只有时间；每道题的读题那一句标成 `Question N`；随后 `align_transcripts.py` 补上 `text` 和 `speaker`，见下面"听力逐字稿"）。作答静音数不出 25 段时依次再试：把被杂音隔开的静音连起来；底噪高的录音（ffmpeg 静音检测切不开句子、作答时间里也有杂音）按帧能量重新找静音。都不行就整段录音当一段，不设题组的 `audioSegment`

几点说明：

- 答案和解析都从"解析"PDF 里取。解析有文字层的直接用，扫描件先识别（`data/cache/cet-ocr/` 里缓存识别结果，可以删）。答案取不全、选词填空答案有重复、题组对不上，这套就跳过，不会导入一半
- 取答案的句式在 `scripts/cet_answers.py`：`答案为 C)`、`X）【精析】`、`选项 B……故为正确答案`、`……出现在 B 段`（段落匹配）、块首行末尾单独的答案字母等。选词填空的解析多半只写词（"备选名词中 mood 符合句意，故为答案"），导入时按原卷词库（Section A 后面的 `A) … O) …`）把词对回字母，结尾恰好提到词库里一个词才取；卷末的"答案速查表"（一页上有 8 行以上单独的 `54. B`）不当作题号。左右两栏并排的页，右栏的题号在文字层里排在左栏前面，漏掉的题号单独补回来。整块取和按栏取的答案不一致的题仍然不要
- 有的套卷面不列听力或阅读（听力和阅读与同场另一套相同），导入时只有卷面上有的部分，然后由 `scripts/share_listening.py` 把同场那一套的听力接上（见下一节）；只剩写作和翻译的套（一页纸）也会导入，但不进目录
- 个别题号在扫描件上认错了位置（如第 3 套选词填空的空位"30"没认出来，被认到了"Part II … (30 minutes)"的 30 上），核对卷面图后写在 `import_cet.py` 的 `NUMBER_FIX` 里
- 原卷是网络转载的扫描版，文字层是扫描识别出来的，个别词有错字（如 `for` 识别成 `fbr`），会影响点词查词
- 扫描页识别很慢（一页十几秒到几十秒，按进程数并行），第一次导入全部要几十分钟
- 跳过的套：文字层乱码、纯图片扫描件、缺真题卷或解析的，以及解析版式特殊、答案没法可靠取出的。用 `--all` 跑完会列出每套的状态和原因

### 四六级第 3 套的听力

每场只考两套听力，第 3 套（2020-09、2022-06 是第 2 套）的听力和同场另一套是同一份录音，只是选项顺序不同，原卷只印一句"本套听力与第 X 套相同"。`scripts/share_listening.py` 把那一套的听力接进来，做成完整的一套（57 题）：

- 卷面：把那一套从"Part II Listening Comprehension"到"Part III Reading Comprehension"之前的部分裁下来，插到本套写作和阅读之间，本套那段说明去掉；不满一页的几段叠在一页里。覆盖 `public/papers/pdf/<id>.pdf` 和 `.words.json`
- 题目、答案、录音、逐字稿照搬那一套（答案键和接进来的卷面是同一种选项顺序），这个部分标 `from`；试卷记 `shared`，`note` 里写一句
- 解析层：补上这些听力题；本套自己的题按 `locate.quote` 在新卷面上重新定位
- 接哪一套：原卷写明了的照写的；只写"与前两套相同"的（不同考区第 3 套配的听力不同，两套都真考过），接逐字稿和解析更全的那套，一样全就接第 2 套。cet6-2021-12-3 的选词填空也没印（和第 1 套相同），一起接
- 第一次运行时把导入的原样存在 `data/cache/cet-shared/<id>/`，以后都从原样重做，可以重复运行。**重导了第 3 套、或者改了被借的那一套（答案、逐字稿、解析）之后，要重跑一次**：`python -I scripts/share_listening.py`；`--dry-run` 只打印怎么拼，`--check` 逐词核对新卷面
- `align_transcripts.py` 对齐逐字稿时跳过这些套（对齐被借的那套，再重跑 share_listening）
